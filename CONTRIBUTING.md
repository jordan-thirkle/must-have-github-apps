# Contributing

Thanks for helping make GitHub Apps easier to discover and evaluate.

## What makes a useful contribution

A good entry is practical, current, and honest. Include:

- the problem the app solves;
- the intended audience and repository size or workflow;
- the permissions it requests and why they are needed;
- setup requirements and maintenance overhead;
- current pricing or meaningful free-tier limits;
- security, privacy, and data-retention considerations;
- limitations and reasonable alternatives;
- links to official documentation and the official listing.

Firsthand experience is valuable, but separate observed behaviour from assumptions. Do not claim that a tool guarantees security or prevents every vulnerability.

## Pull requests

- Keep each pull request focused.
- Use a descriptive title.
- Prefer official sources for permissions, pricing, and capabilities.
- Do not include secrets, private customer information, or copied proprietary text.
- Disclose affiliate relationships or sponsored placement.
- Run the relevant checks before opening a pull request.

## Review standard

Entries may be rejected or revised when they are outdated, promotional without evidence, unclear about permissions, or not meaningfully useful to GitHub users.

## Code of conduct

Be respectful, specific, and constructive. Harassment, discrimination, personal attacks, and deliberate misinformation are not welcome.
